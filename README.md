# Table Importer

**Table Importer** — библиотека на Python для предварительного анализа и импорта табличных данных из **CSV**, **Excel (.xlsx)** и **SQLite** через единый программный интерфейс.

Проект разработан в рамках тестового задания. Приоритеты реализации — понятный API, расширяемая архитектура, контролируемое чтение данных по частям и предсказуемая обработка ошибок.

## Возможности

- **Три типа источников:** CSV, XLSX (в том числе файлы с несколькими листами), базы данных SQLite.
- **Единый API:** `get_tables()`, `scan()`, `load()`, `create_session()`.
- **Предварительное сканирование:** ограниченное число строк; названия столбцов, предполагаемые типы и количество пропусков в выборке.
- **Метаданные о размере:** информация об общем количестве строк там, где она доступна, с явным указанием ограничений.
- **Чтение по частям:** настраиваемый `chunk_size`.
- **Управляемая сессия:** пауза и возобновление импорта без повторного чтения уже полученных чанков в рамках работающего процесса.
- **Прогресс:** количество успешно обработанных строк и состояние сессии.
- **Преобразование типов:** числовые и datetime-типы, режимы обработки ошибок `raise` и `coerce`.
- **Пользовательские исключения:** отдельные классы ошибок источников и преобразования данных.
- **Автоматические тесты:** `pytest`, включая временные файлы и SQLite-базы.

## Требования

- Python **3.10+**
- `pandas`
- `openpyxl`
- `sqlite3` входит в стандартную библиотеку Python
- `pytest` — только для разработки и тестирования

## Быстрый старт

### CSV

```python
from table_importer import TableImporter

importer = TableImporter("data/users.csv")

# Получаем список доступных таблиц (для CSV это одна таблица).
print(importer.get_tables())

# Анализируем до 100 строк, не загружая файл целиком.
metadata = importer.scan(limit=100)
print(metadata)

# Загружаем данные в один DataFrame порциями по 1000 строк.
df = importer.load(chunk_size=1000)
print(df.head())
```

### Excel (.xlsx)

```python
from table_importer import TableImporter

importer = TableImporter("data/sales.xlsx")

# В Excel таблицами считаются отдельные листы.
print(importer.get_tables())

metadata = importer.scan(table="January", limit=100)
df = importer.load(table="January", chunk_size=1000)
```

### SQLite

```python
from table_importer import TableImporter

importer = TableImporter("data/shop.db")

# Получаем названия пользовательских таблиц базы.
print(importer.get_tables())

metadata = importer.scan(table="users", limit=100)
df = importer.load(table="users", chunk_size=1000)
```

Для источника с **одной** таблицей её имя можно не передавать. Если листов или таблиц несколько, `table` следует указать явно — библиотека не выбирает произвольную таблицу молча.

## Предварительное сканирование

Метод `scan(table=None, limit=1000)` исследует ограниченную выборку, возвращая словарь с метаданными. Пример структуры результата:

```python
{
    "name": "users",
    "rows": {
        "sampled": 100,
        "total": None,
        "estimated": True,
    },
    "columns": {
        "count": 3,
        "names": ["id", "name", "age"],
    },
    "dtypes": {
        "id": "int64",
        "name": "object",
        "age": "float64",
    },
    "missing_values": {
        "id": 0,
        "name": 2,
        "age": 1,
    },
}
```

Значения в примере иллюстративные. `missing_values` и `dtypes` относятся **к просмотренной выборке**, а не обязательно ко всему источнику. Определённые по выборке типы могут отличаться от типов после полного импорта.

Особенности определения размера:

| Источник | Полное число строк |
| --- | --- |
| CSV | Не вычисляется при ограниченном сканировании (`total=None`), поскольку точный подсчёт требует полного прохода по файлу. |
| XLSX | Берётся из границ листа (`max_row` минус строка заголовков). Это показатель границы используемого диапазона, а не гарантированное число непустых записей. |
| SQLite | Вычисляется запросом `COUNT(*)`. Значение точное для результата запроса, но на больших таблицах подсчёт может быть дорогим. |

Поле `estimated` отражает выбранную реализацию описания размера; оно **не гарантирует**, что оценка является статистически достоверной. Для Excel границы листа могут включать пустые строки.

## Итерационный импорт и управление сессией

Метод `load()` возвращает один итоговый `pandas.DataFrame`. Для ручного управления загрузкой предназначен `create_session()`:

```python
from table_importer import TableImporter

importer = TableImporter("data/users.csv")
session = importer.create_session(chunk_size=1000)

first_chunk = session.next_chunk()
print("Загружено строк:", session.processed_rows)

# Приостанавливаем загрузку между чанками.
session.pause()
print(session.progress)

# Уже обработанные строки остаются доступны.
partial_df = session.get_dataframe()

# Продолжаем с текущей позиции итератора.
session.resume()
final_df = session.load_all()

print("Завершено:", session.is_finished)
print("Всего строк:", len(final_df))
```

Свойства `processed_rows`, `is_paused`, `is_finished` и `progress` позволяют отслеживать состояние процесса. Прогресс выражается количеством обработанных строк и статусом; процент не гарантируется, поскольку общее число строк может быть неизвестно.

**Семантика паузы:** `pause()` не прерывает уже выполняющееся чтение чанка и не сохраняет состояние на диск. Возобновление возможно, пока объект сессии и процесс Python существуют. При ошибке преобразования текущий чанк может быть уже прочитан источником; для повторной обработки лучше создать новую сессию.

## Преобразование типов

Типы задаются словарём `dtype`:

```python
from table_importer import TableImporter

importer = TableImporter("data/users.csv")

df = importer.load(
    chunk_size=1000,
    dtype={
        "age": "Int64",
        "salary": "float64",
        "created_at": "datetime64[ns]",
    },
    conversion_errors="raise",
)
```

Доступны две политики:

- `conversion_errors="raise"` (по умолчанию) — ошибка при невозможности преобразования.
- `conversion_errors="coerce"` — для поддерживаемых числовых и datetime-преобразований некорректные значения заменяются пропусками.

`Int64` (с заглавной `I`) — nullable-целочисленный тип pandas, допускающий пропуски. Для некоторых остальных типов применяется обычный `astype()`, который может не поддерживать режим `coerce`.

**Важно:** преобразование выполняется для каждого чанка отдельно. На неоднородных данных возможны отличия в автоматически определённых типах между чанками, если тип не задан явно.

## Обработка ошибок

Библиотека определяет следующие исключения:

| Исключение | Назначение |
| --- | --- |
| `TableImporterError` | Общий базовый класс исключений библиотеки |
| `UnsupportedSourceError` | Неподдерживаемый формат источника |
| `SourceNotFoundError` | Файл или база данных не найдены |
| `TableNotFoundError` | Указанный лист или таблица отсутствует |
| `DataConversionError` | Ошибка преобразования столбца |
| `SourceReadError` | Ошибка чтения источника |

```python
from table_importer import TableImporter, TableImporterError

try:
    df = TableImporter("data/users.csv").load()
except TableImporterError as error:
    print(f"Ошибка импорта: {error}")
```

Исключения чтения ещё не обязательно унифицированы во всех ветвях работы библиотеки; некоторые ошибки сторонних библиотек могут передаваться напрямую. Это область дальнейшего улучшения.

## Архитектура

```text
table_importer/
├── __init__.py          # Публичный API
├── importer.py          # TableImporter: выбор источника и операции
├── session.py           # ImportSession: загрузка, пауза, прогресс
├── metadata.py          # TableMetadata: структура метаданных
├── converters.py        # Преобразование типов столбцов
├── exceptions.py        # Собственные исключения
└── sources/
    ├── __init__.py
    ├── base.py           # Абстрактный интерфейс DataSource
    ├── csv_source.py     # CSVSource
    ├── excel_source.py   # ExcelSource
    └── sqlite_source.py  # SQLiteSource
```

```text
                   TableImporter
                        |
                   DataSource
                 /      |      \
         CSVSource  ExcelSource  SQLiteSource
                        |
            Iterator[pandas.DataFrame]
                        |
                   ImportSession
                        |
              pandas.DataFrame
```

`DataSource` определяет общий контракт: `get_tables()`, `scan(table, limit)` и `iter_chunks(table, chunk_size)`. Адаптеры инкапсулируют особенности конкретных источников. `TableImporter` предоставляет единый интерфейс, а `ImportSession` отделяет процесс управления чтением от формата файла.

Для добавления нового источника нужно реализовать контракт `DataSource` и зарегистрировать новый тип в механизме выбора источника (`TableImporter._create_source()`). **Регистрация пока выполняется явно в фабричном методе**; полноценного реестра плагинов нет.

## Принятые решения и компромиссы

1. **Адаптеры источников.** Разные форматы имеют разную механику чтения, но предоставляют одинаковые операции. Это уменьшает связность кода.
2. **Частичное сканирование.** Мы не читаем весь CSV ради статистики по первым строкам. Если для получения размера требуется полный проход, это явно отражается в метаданных.
3. **`openpyxl` с `read_only=True` для XLSX.** Такой подход позволяет последовательно читать строки и формировать чанки. `data_only=True` читает сохранённые результаты формул; если их нет, значение может оказаться пустым.
4. **Стандартный `sqlite3`.** Для SQLite не требуется внешняя ORM. Подключение выполняется в режиме чтения, а имена таблиц проверяются и экранируются.
5. **Пауза без потоков.** Сессия сохраняет положение итератора; это проще, чем фоновые задачи, но пауза доступна лишь между чанками и не переживает перезапуск процесса.
6. **Один итоговый DataFrame.** Чтение выполняется по частям, но `load()` собирает их в памяти. Поэтому объём доступной RAM должен быть достаточен для всего результата. Это ограничение продиктовано требованием возвращать один DataFrame.
7. **Явное указание листа/таблицы.** Если источник содержит несколько таблиц, пользователь должен выбрать нужную, чтобы избежать случайного импорта.
8. **Ошибки преобразования по умолчанию не игнорируются.** `raise` выбран как безопасное поведение: некорректные исходные данные не должны незаметно изменяться.

## Известные ограничения

- Поддерживается XLSX, но не старый формат `.xls`.
- Для CSV общее число строк не вычисляется в режиме быстрого сканирования.
- Метаданные о пропусках и типах относятся только к просмотренной выборке.
- Чтение Excel опирается на первую строку как на заголовки; нестандартные, пустые или дублирующиеся заголовки требуют дополнительных проверок.
- Нет восстановления остановленной сессии после завершения процесса Python.
- Пока нет гарантированного процента выполнения без известного общего числа строк.
- Полная загрузка возвращает один DataFrame, поэтому не является решением для данных, которые целиком не помещаются в память.
- Не во всех сценариях ошибки чтения сторонних библиотек преобразуются в `SourceReadError`.
